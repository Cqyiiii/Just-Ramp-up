What was changed and why

The original repository distributed experimental logic across 37 notebooks with duplicated graph loading, randomization, outcome functions, model training and result handling. The user requested maintainability and reproducibility, a polished NeurIPS 2026 README, and a push back to the same repository. The latest supplied manuscript defines the intended experimental settings.

The maintained rampup package now separates those responsibilities and exposes a configuration-driven CLI. Historical notebooks and result arrays remain available in place. The new engine corrects node/feature alignment and dynamic-graph forwarding, records realized experimental designs, and commits complete repetitions atomically. Each run includes its own offline report.

Frozen verification design and gates

The confirmatory engineering checks are numerical tests on hand-computed fixtures, real GNN stage-graph/determinism tests, recovery/corruption/concurrency tests, CLI integration, all six outcome families across four merge/level combinations, and a distributable wheel build. Acceptance requires a zero test/build exit code and valid complete records for every execution case. No accuracy threshold or paper-effect confirmation is imposed on small smoke runs.

The five execution cases were chosen before execution to cover OLS, GNN, dynamic stage graphs, sparse two-hop interference on Stanford, and the near-zero cluster baseline. Their seed is 2026; GNN initialization uses seed 2. Synthetic cases use 60 nodes and three proportions; real cases use the five paper proportions. OLS and GNN results from different configurations are not a controlled estimator comparison.

# Migration from the original notebooks

The original 37 notebooks, `Dataset/`, `Result/` and `table_output.py` remain at their original paths. They are a historical record; the maintained execution interface is now `python -m rampup`. Saved `.pkl` arrays are not loaded or reinterpreted by the new runner. Legacy notebooks may depend on cell order, missing intermediate files and their original package environment.

## Material scientific and reproducibility differences

| Area | Historical implementation | Maintained runner |
|---|---|---|
| Unit IDs | Some assignments use array indices 0..n−1 as labels in a graph labelled 1..n. | Canonical IDs and row indices are explicit and aligned. |
| GNN feature order | Features iterate NetworkX insertion order; `dgl.from_networkx` may relabel in sorted order. | Sparse adjacency, treatment, outcomes and GNN features share sorted original IDs. |
| Dynamic graphs | Some notebooks train every stage on the final `dgl_G`, and use old cluster labels on newly indexed graphs. | Each stage carries its own graph; original node mapping and baseline clusters are preserved. Evaluation uses the last selected stage's graph. |
| Treatment count | Quantile comparisons (`<` versus `<=`) can produce different counts. | Complete randomization treats exactly floor(p × number of entities). Realized unit and entity counts are recorded. |
| Near-zero baseline | Several notebooks use no treated entities at p=0; others use one. | `baseline="one"` follows the latest manuscript. `baseline="zero"` explicitly chooses true global control. |
| Temporal independence | Some `no_ramp` notebooks redraw randomness between merge groups but share it within a group. | `temporal="independent"` draws a new assignment at every stage. |
| Repeated experiments | Repeat notebooks reuse an identical set of treated units. | `merge="repeated"` repeats the final propensity; `temporal` explicitly chooses shared or independent assignments. |
| Stage outcomes | Noise can be redrawn as a group is reconstructed. | Each stage is generated once per repetition and shared by merge comparisons. Group comparisons are paired. |
| Two-hop interference | Dense adjacency and matrix powers; some HT notebooks require a missing `A_2hop.pkl`. | Sparse matvecs and analytic diagonal removal; true GATE derives from the actual graph. |
| Dynamic evolution | Seed may reset at each stage; node insertion order affects candidate IDs. | One explicit graph-seed stream, fixed canonical IDs, recorded edge counts. |
| Repetition count | GNN notebooks allocate 1000 rows; the current manuscript reports 100 repetitions. | Paper presets use 100; the frozen run config records overrides. |
| Completion state | Preallocated zero rows can be summarized after an interrupted run. | A checkpoint exists only after the entire repetition completes; genuine numerical zeros are retained. |
| Summary | `table_output.py` requires manual result paths and a manually selected true GATE. | Summaries use each group's graph-specific truth and only validated complete records. |

These corrections preserve the intended formulas and architecture, not the exact historical random streams or numerical arrays. **Do not treat new outputs as bitwise reproductions of the published tables.** The old outputs have not been overwritten, certified or used as newly executed results.

Objective and experimental design

GATE is the difference between mean potential outcomes under global treatment and global control. The study examines whether training a regression model on multiple treatment proportions improves this extrapolation under network interference. These runs quantify configured scenarios; no automatic hypothesis acceptance gate is imposed.

Design reference: the supplied NeurIPS 2026 manuscript, Just Ramp-Up: Debiasing Regression-based Estimator for A/B Tests under Network Interference, simulation study and detailed-experiment appendices. The linked preprint may retain its earlier title: arXiv:2410.12740.

Each repetition has independent assignment and noise random streams derived from its root seed and repetition ID. Stages are generated once and reused across merge groups. Complete randomization selects floor(p × entity count) entities; cluster assignments preserve membership. A one-entity baseline differs from exact global control. The latest selected stage supplies the graph used for counterfactual evaluation.

Methods, provenance and diagnostics

Node IDs are sorted once and shared by adjacency, treatment, features and responses. Graphs must be simple, unweighted and have no isolated nodes. Two-hop interference uses Wz + r₂[W(Wz) − diag(W²)z], with W = D⁻¹A; the diagonal removes closed walks without constructing a dense squared adjacency. True GATE is computed by averaging the noise-free global-treatment and global-control outcomes on the evaluation graph.

OLS fits an intercept and treatment on pooled observations. GNN uses three DGL ChebConv layers (2→16, K=2), (16→16, K=1), (16→1, K=1), ReLU, degree and treatment features, and Adam with betas (0.9, 0.999). Each epoch steps the optimizer through the selected stages in order, using each stage’s own graph. No held-out predictive test set or model-selection search is used.

Dynamic graphs are fixed across repetitions and evolve independently of treatment: each node at or above the degree median gets five candidate neighbors drawn with replacement proportional to current degree; loops and existing edges are discarded. Initial cluster membership stays fixed. Recorded edge counts are realized values, not a promise to match historical notebook RNG output.

Objective and experimental design

GATE is the difference between mean potential outcomes under global treatment and global control. The study examines whether training a regression model on multiple treatment proportions improves this extrapolation under network interference. These runs quantify configured scenarios; no automatic hypothesis acceptance gate is imposed.

Design reference: the supplied NeurIPS 2026 manuscript, Just Ramp-Up: Debiasing Regression-based Estimator for A/B Tests under Network Interference, simulation study and detailed-experiment appendices. The linked preprint may retain its earlier title: arXiv:2410.12740.

Each repetition has independent assignment and noise random streams derived from its root seed and repetition ID. Stages are generated once and reused across merge groups. Complete randomization selects floor(p × entity count) entities; cluster assignments preserve membership. A one-entity baseline differs from exact global control. The latest selected stage supplies the graph used for counterfactual evaluation.

Methods, provenance and diagnostics

Node IDs are sorted once and shared by adjacency, treatment, features and responses. Graphs must be simple, unweighted and have no isolated nodes. Two-hop interference uses Wz + r₂[W(Wz) − diag(W²)z], with W = D⁻¹A; the diagonal removes closed walks without constructing a dense squared adjacency. True GATE is computed by averaging the noise-free global-treatment and global-control outcomes on the evaluation graph.

OLS fits an intercept and treatment on pooled observations. GNN uses three DGL ChebConv layers (2→16, K=2), (16→16, K=1), (16→1, K=1), ReLU, degree and treatment features, and Adam with betas (0.9, 0.999). Each epoch steps the optimizer through the selected stages in order, using each stage’s own graph. No held-out predictive test set or model-selection search is used.

Dynamic graphs are fixed across repetitions and evolve independently of treatment: each node at or above the degree median gets five candidate neighbors drawn with replacement proportional to current degree; loops and existing edges are discarded. Initial cluster membership stays fixed. Recorded edge counts are realized values, not a promise to match historical notebook RNG output.

Methods, provenance and diagnostics

Node IDs are sorted once and shared by adjacency, treatment, features and responses. Graphs must be simple, unweighted and have no isolated nodes. Two-hop interference uses Wz + r₂[W(Wz) − diag(W²)z], with W = D⁻¹A; the diagonal removes closed walks without constructing a dense squared adjacency. True GATE is computed by averaging the noise-free global-treatment and global-control outcomes on the evaluation graph.

OLS fits an intercept and treatment on pooled observations. GNN uses three DGL ChebConv layers (2→16, K=2), (16→16, K=1), (16→1, K=1), ReLU, degree and treatment features, and Adam with betas (0.9, 0.999). Each epoch steps the optimizer through the selected stages in order, using each stage’s own graph. No held-out predictive test set or model-selection search is used.

Dynamic graphs are fixed across repetitions and evolve independently of treatment: each node at or above the degree median gets five candidate neighbors drawn with replacement proportional to current degree; loops and existing edges are discarded. Initial cluster membership stays fixed. Recorded edge counts are realized values, not a promise to match historical notebook RNG output.

Limitations and next step

  • Small repetition/epoch counts verify execution only; accuracy rankings and paper-level scientific conclusions are unsupported.
  • A corrected implementation changes historical node alignment, rounding and random streams; historical numerical equality is not claimed.
  • Uncertainty intervals describe Monte Carlo error conditional on this graph, configuration and model initialization; they are not causal confidence intervals for a real deployment.
  • Groups reuse stage data within each repetition and are dependent; marginal intervals do not test between-group differences.
  • GNN architecture is retained, but library versions can affect optimization. No full paper replication gate is evaluated automatically.

Inspect the diagnostics and migration notes before commissioning the full paper settings. Engineering tests and smoke runs do not establish the manuscript’s scientific results. Methods, provenance and diagnostics

Node IDs are sorted once and shared by adjacency, treatment, features and responses. Graphs must be simple, unweighted and have no isolated nodes. Two-hop interference uses Wz + r₂[W(Wz) − diag(W²)z], with W = D⁻¹A; the diagonal removes closed walks without constructing a dense squared adjacency. True GATE is computed by averaging the noise-free global-treatment and global-control outcomes on the evaluation graph.

OLS fits an intercept and treatment on pooled observations. GNN uses three DGL ChebConv layers (2→16, K=2), (16→16, K=1), (16→1, K=1), ReLU, degree and treatment features, and Adam with betas (0.9, 0.999). Each epoch steps the optimizer through the selected stages in order, using each stage’s own graph. No held-out predictive test set or model-selection search is used.

Dynamic graphs are fixed across repetitions and evolve independently of treatment: each node at or above the degree median gets five candidate neighbors drawn with replacement proportional to current degree; loops and existing edges are discarded. Initial cluster membership stays fixed. Recorded edge counts are realized values, not a promise to match historical notebook RNG output.

Limitations and next step

  • Small repetition/epoch counts verify execution only; accuracy rankings and paper-level scientific conclusions are unsupported.
  • A corrected implementation changes historical node alignment, rounding and random streams; historical numerical equality is not claimed.
  • Uncertainty intervals describe Monte Carlo error conditional on this graph, configuration and model initialization; they are not causal confidence intervals for a real deployment.
  • Groups reuse stage data within each repetition and are dependent; marginal intervals do not test between-group differences.

Objective and experimental design

GATE is the difference between mean potential outcomes under global treatment and global control. The study examines whether training a regression model on multiple treatment proportions improves this extrapolation under network interference. These runs quantify configured scenarios; no automatic hypothesis acceptance gate is imposed.

Design reference: the supplied NeurIPS 2026 manuscript, Just Ramp-Up: Debiasing Regression-based Estimator for A/B Tests under Network Interference, simulation study and detailed-experiment appendices. The linked preprint may retain its earlier title: arXiv:2410.12740.

Each repetition has independent assignment and noise random streams derived from its root seed and repetition ID. Stages are generated once and reused across merge groups. Complete randomization selects floor(p × entity count) entities; cluster assignments preserve membership. A one-entity baseline differs from exact global control. The latest selected stage supplies the graph used for counterfactual evaluation.

Methods, provenance and diagnostics

Node IDs are sorted once and shared by adjacency, treatment, features and responses. Graphs must be simple, unweighted and have no isolated nodes. Two-hop interference uses Wz + r₂[W(Wz) − diag(W²)z], with W = D⁻¹A; the diagonal removes closed walks without constructing a dense squared adjacency. True GATE is computed by averaging the noise-free global-treatment and global-control outcomes on the evaluation graph.

OLS fits an intercept and treatment on pooled observations. GNN uses three DGL ChebConv layers (2→16, K=2), (16→16, K=1), (16→1, K=1), ReLU, degree and treatment features, and Adam with betas (0.9, 0.999). Each epoch steps the optimizer through the selected stages in order, using each stage’s own graph. No held-out predictive test set or model-selection search is used.

Dynamic graphs are fixed across repetitions and evolve independently of treatment: each node at or above the degree median gets five candidate neighbors drawn with replacement proportional to current degree; loops and existing edges are discarded. Initial cluster membership stays fixed. Recorded edge counts are realized values, not a promise to match historical notebook RNG output.

Limitations and next step

  • Small repetition/epoch counts verify execution only; accuracy rankings and paper-level scientific conclusions are unsupported.
  • A corrected implementation changes historical node alignment, rounding and random streams; historical numerical equality is not claimed.
  • Uncertainty intervals describe Monte Carlo error conditional on this graph, configuration and model initialization; they are not causal confidence intervals for a real deployment.
  • Groups reuse stage data within each repetition and are dependent; marginal intervals do not test between-group differences.
  • GNN architecture is retained, but library versions can affect optimization. No full paper replication gate is evaluated automatically.

Inspect the diagnostics and migration notes before commissioning the full paper settings. Engineering tests and smoke runs do not establish the manuscript’s scientific results. HT notebooks remain historical references; this runner does not implement the paper’s MII, Hájek, Lagrange or missing MIT8 experiments.
